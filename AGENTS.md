# Dotfiles — контекст для агента

Пользовательская документация (установка, обновление, удаление, использование) — в `README.md`. Здесь то, что нужно знать перед правками: как устроен репозиторий, как с ним работать и что важно в каждом конфиге по отдельности.

## Репозиторий

Использование: bare-репозиторий `~/.dotfiles` с рабочим деревом `$HOME`, поэтому пути в репозитории совпадают с путями домашнего каталога.

Редактирование: в обычной рабочей копии (отдельном клоне репозитория) — документация, правки и проверки.

### Правила

- В репозиторий идёт только то, что переезжает на другую машину и описывает общие настройки.
- Файлы конфигов проверяются на работоспособность и корректность.
- Файлы `AGENTS.md` и `README.md` — документация репозитория: в `$HOME` она не развёртывается, эти файлы исключены через `sparse-checkout`.
- Файла `.gitignore` нет. Локальных конфигов линтеров (`.markdownlint.jsonc`, `.cspell.json`, `.prettierrc` и подобных) в дереве нет: это лишние дотфайлы в `$HOME`. Правила передаются флагами или временным файлом (см. «Проверки»).
- Файлы с личной или секретной информацией (`.ssh/`, `.gnupg/`, `.aws/`, `*credentials*`) не добавляются никогда: репозиторий публичный.

### Новый конфиг

Порядок добавления любого нового файла:

1. **Путь.** Корень репозитория — это `$HOME`, поэтому файл лежит там, где его ищет сама программа. Если программа умеет читать файлы из нескольких мест, `.config/` предпочтительнее.
2. **Раздел в «Инструментах».** На каждый конфиг — свой раздел: заголовок `<tool>` или `<tool> — <что именно>`, путь `~/…`, содержимое и пояснение, почему значения такие.
3. **Проверка.** Файл добавляем, только если его можно проверить: вносим в команды из «Проверок», а если формат линтером не покрыт — добавляем новый блок в общий список проверок.

### Обёртка `dotfiles`

Утилита `~/.local/bin/dotfiles` — тонкая обёртка над git: `git --git-dir="$HOME/.dotfiles" --work-tree="$HOME"` с коротким `status` по умолчанию, остальные аргументы передаются git как есть. Ничего не добавляет к поведению git и не хранит состояния.

### Проверки

```bash
# bash
shellcheck .local/bin/*
shfmt -i 4 -s -d .local/bin/*

# markdown: npm i -g markdownlint-cli; --trailing-comma none — из-за JSONC-примеров
# --prose-wrap never — абзац одной строкой, поэтому MD013 выключен
prettier --parser markdown --prose-wrap never --trailing-comma none --check AGENTS.md README.md
prettier --parser markdown --prose-wrap never --trailing-comma none --write AGENTS.md README.md
markdownlint --disable MD013 -- AGENTS.md README.md

# орфография: npm i -g cspell @cspell/dict-ru_ru, конфиг временный
# в words только слова, которых нет в словаре: настоящая опечатка должна падать
g=$(npm root -g)
cfg=$(mktemp --suffix=.json)
cat >"$cfg" <<EOF
{
  "version": "0.2",
  "language": "ru,en",
  "import": ["$g/@cspell/dict-ru_ru/cspell-ext.json"],
  "words": [
    "бэкапов",
    "дотфайлы",
    "коммитом",
    "конфигами",
    "конфигов",
    "autofetch",
    "esac",
    "mktemp",
    "pipefail",
    "shellcheck",
    "shfmt"
  ]
}
EOF
cspell --config "$cfg" --no-progress \
    AGENTS.md README.md .local/bin/dotfiles
rc=$?
rm -f "$cfg"
[ "$rc" -eq 0 ]
```
